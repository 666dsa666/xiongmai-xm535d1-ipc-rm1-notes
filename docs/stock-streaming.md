# Stock streaming — ports, RTSP, ONVIF

All observations below are from the camera on `192.168.0.152`, stock firmware, no modification.

## Ports

| port | service | notes |
|---|---|---|
| 80 | HTTP web UI | title `Web Viewer` (Xiongmai web viewer) |
| 554 | RTSP | `Server: H264DVR 1.0` |
| 8899 | ONVIF | `Server: hsoap/2.8` (happytimesoft stack) |
| 34567 | Xiongmai P2P | used by the mobile app |
| 23 | closed | no telnet by default |

## RTSP

DESCRIBE on `rtsp://<ip>:554/` returns `401 Unauthorized` with
`WWW-Authenticate: Digest realm="…", nonce="…"`.

The Xiongmai form embeds the credentials in the path and returns `200 OK` + SDP:

```
rtsp://<ip>:554/user=admin_password=_channel=1_stream=0.sdp?real_stream
```

(`password=` empty = the default blank password.)

SDP for the main stream:

```
m=video 0 RTP/AVP 98
a=rtpmap:98 H265/90000
a=fmtp:98 profile-id=010101; sprop-pps=…; sprop-sps=…; sprop-vps=…
a=framerate:25
m=audio 0 RTP/AVP 8        ; PCM A-law
```

`ffprobe -rtsp_transport tcp -count_frames`:

| URL | codec | size | frames in 5 s |
|---|---|---|---|
| `…_channel=1_stream=0.sdp?real_stream` | HEVC | 2304×2592 | 60 |
| `…_channel=1_stream=1.sdp?real_stream` | HEVC | 640×720 | 60 |

HEVC decoders may log `Could not find ref with POC …` when attaching mid-GOP; this is normal and does not
prevent playback (wait for the next IDR).

## ONVIF

Endpoint: `http://<ip>:8899/onvif/device_service` and `/onvif/media_service`.
`GetSystemDateAndTime` and `GetProfiles` answer **without authentication** on this firmware.

Profiles:

| token | name | encoding | resolution |
|---|---|---|---|
| `000` | mainStream | H264 | 3072×2048 |
| `001` | subStream | H264 | 800×448 |
| `002` | snapStream | JPEG | 800×448 |

`GetStreamUri` returns:

```
rtsp://<ip>:554/user=admin_password=tlJwpbo6_channel=0_stream=0&onvif=0.sdp?real_stream
rtsp://<ip>:554/user=admin_password=tlJwpbo6_channel=0_stream=1&onvif=0.sdp?real_stream
rtsp://<ip>:554/user=admin_password=tlJwpbo6_channel=0_stream=2.sdp?real_stream
```

The `tlJwpbo6` token is generated by the device for the current (blank) password; the URIs play as-is.
Note that ONVIF's advertised encoding/resolution (H.264 3072×2048) does not match what the encoder actually
sends over RTSP (HEVC 2304×2592) — trust the SDP/ffprobe values.

## Firmware / device information

`GetDeviceInformation` on `:8899` (no auth on this firmware) returns:

| field | value |
|---|---|
| Manufacturer | `H264` |
| Model | `XM535_X6E-WEQ_8M` |
| FirmwareVersion | `V5.01.R02.000A07F3.10010.346732.S.ONVIF 21.06` |
| HardwareId | `00001` |

The model string identifies the firmware as an **X6E-WEQ** variant (the X6E-WEQ family is what the OpenIPC
`xm535d1` load script was based on, at a newer `V5.07.X02` build).

## Web UI

`http://<ip>/` serves the Xiongmai "Web Viewer". It is the place to change the admin password and the
encoder settings. Default login is `admin` with an empty password.

## Quick verification

```bash
ffprobe -v error -rtsp_transport tcp -read_intervals "%+5" -select_streams v:0 \
        -count_frames -show_entries stream=codec_name,width,height,nb_read_frames \
        -of default=noprint_wrappers=1 \
        'rtsp://<ip>:554/user=admin_password=_channel=1_stream=0.sdp?real_stream'
```

Expected: `hevc`, a real resolution, and a non-zero frame count.
